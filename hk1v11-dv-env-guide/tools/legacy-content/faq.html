FAQ 与遗留问题

  • makefile CHECK target 失效：里面 grep 的是 xrun.log（历史遗留），实际仿真日志叫 sim.log。
  • check.py 缺失：run_tc.sh 会拷贝一个 check.py，但该文件在 script/ 目录下并不存在（可能已丢失或在他人的 script 目录）。
  • merge_coverage.py 硬编码：project_name/user_names 仍是 HV1V21/zjbi，合并覆盖率前需改成 HK1V11 和自己的路径。
  • dummy.cfg 三个坑：① 仅 -p 1 时被读取；② 必须 ≥6 行，每行 ≥3+9 个字符（前 3 字符跳过），有空行会抛 std::out_of_range: basic_string::substr 直接 abort；③ 不能用 Windows CRLF 换行（\r 会被算进 9-bit 串）。
  • run_tc.sh 中 cmodel Run.sh 已注释（约 121 行）：golden 由 isptx_sequence 在仿真中现调现用，不需要手工预跑 cmodel。

新人速查清单

  • 跑一个用例：run_tc.sh TOP t_8b1lane chip_tb_top random clean → 看 $SIM_PATH/TOP_TCON_C/t_8b1lane/sim.log 末尾 TEST CASE PASSED/FAILED。
  • 加用例：cd top/tests && bash create_new_case.sh t_H2560V16_8b1lane_xxx（名字里编码 H/V/FPS/PORT_NUM/寄存器参数），再把名字加进 case_list.txt。
  • 定位 fail：check_sim_results.sh 汇总 → sim.log grep UVM_ERROR（scoreboard 报错自带 frame/line/pixel 和期望/实际值）→ run_tc.sh TOP <case> chip_tb_top verdi 看波形；寄存器 dump 在仿真目录 reg_address_frame_*.log。
  • 关键配置开关：用例 .sv 里 4 个 *_check_on；user_def.sv 里 CHIP_SEL/MULTI_CHIP/CONNECT_NUM/DV；编译宏 CHPI_MODE_420B 切换 8B/10B 与 420b 长编码两套 driver/sequence。
  • 改 golden 行为：cmodel 源码在 cmodel/pic_split_transform/，改完需重新编译 pic_process 并同步到 $DV_TOP_PATH/agents/isprx_env/cmodel/。
